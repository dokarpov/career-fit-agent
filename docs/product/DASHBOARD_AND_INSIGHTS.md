# Dashboard and insight model — v0.9

## Main screen

The main screen is no longer split into Discover / Evidence / Applications / Automation.

The user's recurring job is one cockpit:

1. how long has the search been running?
2. is activity on plan?
3. what is converting?
4. what needs action today?
5. what is the system learning from outcomes?

Evidence is a **profile asset**, not a daily workspace.

It is reviewed:
- at onboarding;
- when a new source arrives;
- when a recurring missing requirement appears;
- when a claim changes state;
- when the system finds contradictory provenance.

## Metrics

### Search days
Observed first tracked application → today.

### Search pace
Tracked role/application threads per week.

### Rejection signals
Outcome emails classified as rejection, reviewable by the user.

### Strong interview signal rate
Strong recruiter/interview events / tracked role threads.

### Efficiency coefficient
`observed interview conversion / market benchmark for current application-volume band`

This is intentionally transparent and narrow. It is not a proprietary magic score.

## Insights after outcomes

After enough outcomes, the system should answer:

- which requirements repeatedly had missing/weak proof in rejected applications?
- which package variants reached recruiter screens/interviews?
- which job sources produced stronger observed yield?
- are target roles drifting away from the verified evidence profile?
- is the user over-applying to one employer?
- are hard constraints wasting application time?
- is a new recurring requirement worth adding to the target profile or building proof for?

Never infer rejection causality from an ATS email alone.
